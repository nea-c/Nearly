# Remembered main-window placement

Nearly remembers the original main window's last normal client size in logical pixels, outer desktop position in physical pixels, and maximized state. Reopening restores the normal geometry before maximizing when requested, so unmaximize retains that geometry. Minimized and fullscreen geometry is ignored; minimized state is never restored.

Only the native window named `main` writes this preference after its settings load succeeds. Ordinary secondary windows open visibly without replacing the original main preference, including after main closes. A single worker debounces resize, move, and scale changes for 350 ms; an authorized main-window close also attempts a final flush. Restore-generated events are gated during native restoration and before settings load. A save failure preserves the previous preference and does not block ordinary closing or sync jobs.

The optional native-only `appearance.windowSize` field contains `width`, `height`, `maximized`, and optional `placement: { x, y }`. Placement accepts signed physical desktop coordinates, including negative positions. Existing size-only documents load without a migration write. Both schemas reject unknown fields; renderer settings DTOs exclude this preference. Native saves keep the existing settings mutex, reread the latest unified document, increment its revision, and preserve unrelated settings. Renderer saves retain the current native preference.

The main window starts hidden. The pure restore plan chooses the current monitor containing or nearest the saved outer position, then clamps the full frame into that monitor's work area. Monitor loss or rearrangement therefore brings an off-screen saved window back into an available work area. Client dimensions use the selected current monitor's scale, never a stored DPI. Windows work areas exclude taskbars using `GetMonitorInfoW` and `MONITORINFO.rcWork`; outer-minus-inner frame dimensions are included in the clamp. The restore plan quantizes client dimensions to whole physical pixels within the available frame budget and floors nonnegative position travel, avoiding fractional-DPI rounding overflow. Native setters receive these planned physical sizes; persisted client dimensions remain logical. The normal minimum is 800 by 650 logical pixels; smaller usable work areas take precedence.

Frameless Windows shadow metrics can change when a hidden window becomes visible. Restoration first places the normal frame inside a work area, shows it after input policy configuration, and reapplies the original client preference using the shown frame. This is one bounded correction, with restore events still gated. The visible correction resizes before repositioning on the already selected monitor. Native readback captures the corrected normal geometry before requested maximize; the session is then seeded while restore events remain gated.

Policy and generated settings-file tests cover size-only migration, negative coordinates, monitor loss/rearrangement, scale change, full-frame clamps, hidden-to-shown frame changes, restore event gating, main-only writes, normal geometry preservation while maximized, minimized/fullscreen exclusion, native field protection, stale settings revisions, concurrent renderer saves, no-op saves, and failed-write preservation. Isolated QA can check current-monitor startup, maximize, restart and unmaximize through actual native getters. Physical mixed-DPI mouse movement and monitor hotplug still require separate desktop verification. The test suite never launches the user's production application.
