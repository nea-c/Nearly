# Whole installation folder removal

Approved scope: continue the ordinary Windows installer in PR34 and add an explicit uninstall option to remove the actual registered installation folder itself and all its contents. D:\Nearly is the example; D:\ is never the deletion scope. This is product implementation permission, not permission to delete existing user-PC data.

Default OFF retains current uninstall behavior and settings. Interactive ON displays the canonical registered target and an explicit Yes/No confirmation defaulting to No. Cancel causes no mutation. Silent uninstall retains data and has no implicit whole-tree flag.

Use existing NSIS, current-user execution, root namespace pins and byte-proven uninstaller identity. No new software, separate deletion service, ACL repair or private-all-ancestor requirement. Store the installed root's volume/file identity in the existing per-user registration. Whole removal requires that recorded identity, the held root and current registered path to match; legacy registrations without it support ordinary OFF uninstall but cannot silently gain whole-tree authority.

Refuse drive roots, Windows and ProgramFiles trees, exact user-profile and important known-folder roots, redirected paths and identity mismatches. The option cannot authorize deleting their parent or following a junction. Root upgrades to a DELETE-capable handle through a bounded reopen under retained ancestor pins, validating the captured identity before any destructive effect.

Whole removal enumerates children under retained directory handles, opens each with OPEN_REPARSE_POINT, inspects the same handle, rejects reparse points and multiply linked files, and sets disposition on that handle. The registered uninstall image remains held and is removed through its existing byte-proven DELETE handle. No path-based recursive deletion or cleanup fallback. Bound traversal depth/count; concurrent additions or unsupported entries fail safely.

Internal contents, including settings and previously unknown files, are in scope only after explicit ON confirmation. Files outside the selected tree remain protected. Partial failure may leave some internal objects deleted and others present; show a specific partial-removal failure, retain registration/uninstaller until the final stage where possible, never claim rollback or successful complete removal. Root removal occurs only when empty and its identity is still pinned.

Validation: RED tests for UI default/confirmation, protected targets, root binding and tree safety; actual NSIS Win32 generated fixtures for OFF/ON/cancel, nested files, outside sentinels, hardlinks/junctions, replacement, late additions, read-only/partial failure and interrupted work. Hosted actual uninstall UI uses an identical copy of the generated guest uninstaller bound to the generated registered root, never the real PC. EN/JA; no full log/settings exports.

Installer destination contract remains local fixed NTFS with existing parent and bounded canonical path while current handle/journal guarantees depend on those primitives. D:\Nearly and E:\Nearly use the same generic drive validator. Explicit E syntax coverage and hosted available-drive coverage must be reported separately from an actual physical E-drive pass. Network shares/exFAT and unrelated installer relocation are outside this change, not silently called qualified.

No main merge, Release, production signing, actual PC install/data removal or modifications to drive ACLs. Preserve prior app/installer artifacts. Source and QA on codex/private-install-directory only. Independent review required before accepting destructive behavior.

Implementation review notes: important-folder ancestors and direct profile roots are refused. Existing short known-folder aliases are normalized for comparison. Root identity mismatch is never overwritten by maintenance; a legacy missing identity may be enrolled by a successful explicit reinstall but ON uninstall without recorded identity is refused. Stronger ancestor handles are matched to the already held FileIDs. Registration removal failure returns nonzero, including after a successful root removal; partial removal is not rollback. The same-handle tree has 32-level/100000-entry/900-character internal traversal limits and refuses rather than clearing read-only attributes or repairing permissions.

Current QA status is recorded separately: native whole-tree and actual uninstall UI need the new hosted run. The first actual option driver covers English Keep/Decline/Remove; Japanese runtime UI remains unverified even though both language strings compile. The prior SHA7d run is not evidence for this feature. Independent review identified and fixed option-page path display, registration error reporting, and test-driver ABI/caption mismatches.

Archive compatibility: temporary payload extraction changes the exact NSIS archive member to `$PLUGINSDIR/Nearly.exe`. The signing producer and signer accept that exact additional literal, preserving the two legacy forms, single-basename uniqueness, streamed extraction, byte identity, hashes, PE checks and signed protocol. Never expand member paths as output directories or relax them to wildcards. Source-bound signing tools must be rebuilt for any later release; this task does no production signing.

API references: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew ; https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle ; https://nsis.sourceforge.io/Docs/Chapter4.html . Sharing checks and DELETE access apply to retained handles; no ACL admission or modification is added.
