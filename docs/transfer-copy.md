# Copying files with Nearly

Use the installed Nearly application with WebView2 Runtime available. Connection credentials remain session-only. Saved bookmarks and folder correspondence do not require keeping a tab open. See the [r2.0 release notes](../.github/release-notes/r2.0.md) for settings compatibility and current verification limits.

Drag local files or folders to the remote list, a remote folder row, or the remote tree. The centered confirmation captures the source, connection, and destination. Folders include their contents. Navigation after confirmation cannot redirect that operation. Remote items can likewise be dragged to the local pane to download copies.

For an existing file, choose Replace, Skip, or Keep both (rename). Apply to all covers matching conflicts in this operation only. Directories merge and retain unrelated children. A file/folder mismatch offers Skip or Keep both; it never recursively deletes an existing directory. Sources are retained.

Files are written to an exclusive staging sibling before publication. Nearly rechecks captured source and destination metadata. Unsupported replacement capabilities or changed targets fail without intentionally deleting the old file. Local overwrite conservatively refuses security metadata or encryption mismatches. Neither SFTP atomic rename nor Windows destination-path replacement supplies an atomic identity compare-and-swap: the final race with an independent external writer cannot be completely excluded. Refresh after a failure or uncertain acknowledgement before retrying. Owned staging files may remain after a lost connection.

The progress gauge counts acknowledged bytes across the whole transfer batch. Scanning, connecting, conflict confirmation, and finalization remain indeterminate; receiving all bytes does not confirm publication. Regular-file sizes must be available, and the complete inventoried batch must total no more than 9,007,199,254,740,991 bytes (about 9 PB), so byte counts remain exact in the interface. Larger or overflowing totals are refused before destination writes or Explorer descriptor publication; use smaller batches. Directories contribute zero bytes. Skipped file bytes are removed from the transfer plan, and empty or all-skipped batches complete only when the operation returns its result.

For Windows Explorer, hold the left button while dragging a remote item out of Nearly. The native provider advertises COPY and a bounded complete list of virtual file descriptors, then streams contents when the receiver requests them. Explorer manages its destination conflicts and any partial output. Nearly does not create an eager temporary copy tree. The provider refuses more than 10,000 entries, depth above 64, unsupported Windows names, or descriptor paths exceeding 259 UTF-16 units; bytes are read in bounded chunks. Cancelling or ending the operation releases its connection and session lease. A stalled asynchronous receiver has a timeout.

The interactive Windows drag loop runs on Tauri's UI thread; metadata and the separate SFTP connection remain on workers. OLE COPY status or a successful stream read alone does not establish Explorer output. External drag/drop cancellation with a short Escape tap and the latest menu/tree interactions in a real native UI remain unverified; see the [r2.0 release notes](../.github/release-notes/r2.0.md). The test harness stops before input when another window covers its owned Explorer destination.

On connection, trees expand toward the current directory and vertically reveal it after pending reads complete. Showing a tree reveals the current directory or its nearest rendered ancestor without opening collapsed descendants or navigating the other pane. Unrelated branches keep their own focus. Keyboard focus uses the normal visible focus ring. Confirmed successful operation cards disappear after five seconds. Cancelled downloads, including native Windows copies, also expire after five seconds; upload cancellations, other file-action cancellations, errors and partial outcomes remain until closed.

Qualification uses generated local files, mock browser RPCs, and localhost SFTP fixtures. Actual Explorer output must be checked separately from DOM routing and COM unit tests. No successful test implies qualification against a user's server, long-running stability, physical hardware gestures, or mixed-DPI/multi-monitor configurations. See the [r2.0 release notes](../.github/release-notes/r2.0.md) for the published qualification limits.
