# Nearly

Windows向けのローカル → SFTP同期アプリです。TypeScript、Tauri 2、Rustで構成されています。公開用ソースとローカル成果物の配置は [project layout](docs/project-layout.md) を参照してください。

## 起動

ビルド後は `build/Nearly.exe` を起動します。WebView2 Runtimeが必要です。接続先のホスト鍵を確認して接続し、同期のローカル・リモートルートを選んで開始します。パスフレーズは設定やログへ保存しません。削除同期は初期状態でOFFです。

本番アプリ識別子 `local.syncfiles.native` は変えません。旧版が動作中の場合は通常の終了操作で閉じてから起動してください。設定の保存先と既存設定の移動については下記を参照してください。

「同期」は、ローカル側で現在開いているフォルダーを同期元にします。「再開」は、そのタブで前回使った同期元・同期先と設定を使い、新しく走査します。再開ボタンへのホバーやキーボードのフォーカスで前回のパスを確認できます。再開の文脈はアプリ再起動では復元しません。

同期中は「再開」を隠します。「同期した場所へ戻る」は同期ボタンの左に表示し、両方の閲覧パネルを前回の同期元・同期先へ戻します。同期は開始しません。場所リンクが非表示でも左側の領域を確保します。「再開」がないときはその空きを畳み、「同期」を右端へ詰めます。

メインウインドウの通常位置・サイズと最大化状態を記録し、次回は利用可能な作業領域内に収めます。全画面状態は記録しません。[今回の操作変更](docs/r2-refinement.md)と[位置とサイズ保存の方針](docs/window-size.md)も参照してください。

サイズと更新日時が同じファイルの送信を省略する差分比較と、削除 ON の対象・注意点は [同期の動作](docs/synchronization.md) を参照してください。

## 開発

前提: Windows、Node.jsとnpm、RustのMSVCツールチェーン、Visual Studio C++ Build Tools、WebView2 Runtime。依存関係の取得には初回ネット接続が必要です。

```powershell
npm ci
npm run tauri -- dev
```

`npm run dev` はブラウザー用の開発表示です。通常は接続方式に SFTP だけを表示し、実SFTPはTauriアプリで使用します。保存済みのモック接続はそのまま保持しますが、接続は無効です。SFTPへ変更する場合は、接続設定で明示的に選択して保存してください。保存や起動だけで接続・転送は行いません。

開発中にシミュレーションを使う場合だけ、環境変数 `NEARLY_ENABLE_MOCK=1` を設定して `npm run dev` を起動します。通常の本番ビルドでは、この環境変数があってもモックは有効になりません。

```powershell
npm test
npm run test:ui
npm run test:ui:production
node scripts/ppk-fixtures.mjs
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

ブラウザーテストはインストール済みMicrosoft Edgeを使用します。ネイティブ・SFTP受入スクリプトは別途用意した隔離アプリと生成フィクスチャ専用です。通常のテストやビルドから自動実行しません。

## Windows EXEのビルド

```powershell
npm run build:windows
# 依存関係を取得済みで、ネットアクセスを使わない場合
npm run build:windows -- --offline
```

出力は `build/Nearly.exe` と `build/build-info.json` です。Cargoのロックファイルを固定してビルドし、成功時だけこの2ファイルを更新します。以前の2ファイルは `build/previous/` へ移して保持します。EXEの隣にある `settings.json` と `settings.backup.json` は変更・移動・同梱しません。配布する際も `build/` 全体をコピーせず、配布用EXEと必要なビルド情報だけを選んでください。通常のビルドではインストーラーを生成しません。

Cargoのキャッシュを別ドライブへ置く場合:

```powershell
$env:CARGO_TARGET_DIR = 'D:\Nearly-cargo-cache'
npm run build:windows -- --offline --locked
```

Gitにはソース、両ロックファイル、ベンダー修正、アイコン、テスト、設計文書を含めます。実行ファイル、依存キャッシュ、ビルド結果、ユーザー設定・秘密鍵、生成した検証記録は含めません。詳細な設計・制約は既存の `docs/` の文書に残しています。

## テーマ

設定メニューから「ライト」「ダーク」「ミッドナイト」を選べます。ダークは無彩色のグレー、ミッドナイトは従来の青みのある暗色です。OSに追従する選択肢はありません。初回にテーマが未設定、または内部の初期値 `system` の場合だけ、OSの明暗からライト／ダークを一度決め、明示したテーマとして保存します。その後のOS設定変更ではテーマを変えません。

## 設定ファイル

設定は、起動した `Nearly.exe` と同じフォルダーの `settings.json`（表示設定）、`history.json`（対応・閲覧履歴）、`bookmarks.json`（ローカル・リモート・ペア）、`sync-profiles.json`（同期設定）、`connections.json`（接続先・確認済みホスト鍵）に分けて保存します。通常のビルドでは `build/` 内です。変更したファイルの直前の内容を各 `*.backup.json` に保持します。EXEは書き込み可能なフォルダーに置いてください。保存先に書き込めない場合、別の場所へ自動保存しません。

認証秘密は保存しません。旧形式からの移行はアプリ外でバックアップを残して一度だけ行い、アプリ内で旧形式を読み込んだり自動移行したりしません。破損・ファイル欠落・更新番号や世代の不整合時は読み込みと保存を拒否し、バックアップを自動復元しません。5 ファイルを一括で原子的に更新する保証はなく、保存中断時は Nearly を終了してから明示的な復旧が必要です。[保存形式と復旧手順](docs/storage-format.md)を参照してください。確認済みホスト鍵は閲覧専用です。未確認の鍵は初回接続時に取得し、内容を確認して承認します。

隔離した開発・受入テストでだけ、`SYNCFILES_CONFIG_DIR` に専用フォルダーを明示して保存先を上書きできます。通常利用ではこの環境変数を設定しないでください。設定には接続情報やローカルパスが含まれるため、Gitや配布物に含めないでください。

## 表示と言語

設定の一番上にある `Language / 言語` で `日本語`・`English` を選べます。既存設定の初期言語は日本語です。その下にテーマ、続いて `コンパクト表示` があります。コンパクト表示は一覧とツリーの行間を詰め、文字サイズは変えません。初期状態はオフです。

言語と表示密度は、他の設定と同じEXE隣の `settings.json` に保存します。プロファイル名・パス・ブックマーク名などの入力内容は翻訳しません。OSや外部ライブラリー由来の詳細メッセージ、技術ログには原文が残る場合があります。詳しい範囲は [表示と言語の設計](docs/display-and-language.md) を参照してください。

## タブとウィンドウ

タブは同じウィンドウ内で並べ替えられ、外へドラッグして分離、別ウィンドウのタブ列へドロップして結合できます。起動中に EXE を再起動すると既存プロセスに空のウィンドウを追加します。自動接続・同期再開はしません。[操作説明](docs/moving-tabs.md) を参照してください。

## 検証範囲と既知の制約

最後のタブを閉じるか移動し終えると、そのウィンドウが閉じます。別ウィンドウの同期は継続します。停止中の同期対象はセッション内で確認・再開でき、再起動時には復元しません。保存済みの接続先ごとに最後の閲覧場所を記憶します。

起動時に新しい安定版を確認し、登録済みのインストールでは、署名と内容を検証して更新できます。同期などの処理中は更新せず、設定保存を確認してから終了・置換・再起動へ進みます。r1.0／r2.0から対応版への初回導入は手動で行ってください。自動更新の対象は正しく登録された `%LOCALAPPDATA%\Nearly` のインストールで、別の場所のEXEや設定は自動移行しません。[更新機能の前提](docs/startup-updates.md)と[r3.0の導入注意点](.github/release-notes/r3.0.md)を参照してください。

モデル・Rust・ブラウザーのテストに加え、別識別子の隔離 EXE の繰り返し起動と、生成した localhost SFTP サーバーでの転送・ウィンドウ終了後の継続を検証しています。ユーザーの実サーバーや資格情報は検証に使っていません。テスト用の鍵は実行時に生成し、生成物は Git に含めません。

OS の実ポインターによるウィンドウ間ドラッグ、混在 DPI・複数モニターでの挙動は、検証環境で承認されたネイティブ入力ツールを利用できなかったため未検証です。ブラウザー上のイベントや模擬 IPC のテストと区別しています。[実機確認手順](docs/native-drag-manual-qa.md) を参照してください。長時間安定性や転送速度低下の解消も保証していません。

複数ウィンドウで設定の同じ項目を競合編集した場合は、安全側で保存を拒否します。再読み込みだけでは復旧せず、対象ウィンドウの同期を停止してから窓を開き直す必要がある場合があります。

このリポジトリはソースのみです。実設定、認証情報、診断・検証の生データ、バックアップ、生成された鍵、依存キャッシュ、ビルド済み EXE は含みません。

GitHub Actions の手動 Windows ビルドと正式公開の準備は [手動リリース手順](docs/github-release.md) を参照してください。通常の push では公開せず、既定の検証モードではタグ・Release・配布 artifact を作りません。
